## Invariants

- No global queue across unrelated fronts; declared dependencies govern readiness.
- One observable outcome per slice; independently acceptable/reversible features should be split.
- Active overlapping write scopes are blocked; slice-owned out-of-scope edits require explicit expansion authority.
- Claim-time dirty-worktree provenance is captured; file ownership is not inferred from HEAD alone.
- A slice mutating a semantic/contract `decisionScope` conflicts with any active slice using that same scope.
- Final evidence must bind to the exact source snapshot it proves.
- Later source drift turns prior PASS evidence stale; stale slices cannot satisfy dependencies or final seal.
- Browser proof uses real user actionability; forced/DOM-dispatched clicks and test layout tampering cannot prove clickability.
- Tool failures are counted per current item/slice, classified, reconciled, and never reset to zero in historical reporting.
- Every normative decision records authority provenance; agent discovery is not Product Owner authority.
- Future slices require owner/preapproved-plan authority or Coordinator authority bound to an existing non-terminal canonical requirement.
- MASTER is an execution projection, not a replacement for canonical product sources.
- Missing slices never cancel canonical requirements; open requirements block workstream closure.
- Shared governor state is mutated only under the process lock and atomic-write policy.
- Non-blocking accepted follow-ups may carry forward to the next touching slice instead of forcing artificial micro-slices.
- Material decisions/learnings are durably routed during implementation. Non-material technical learnings may be canonized autonomously with provenance; material product/authority changes require Coordinator-mediated real `/GRILL-ME` according to project policy.
- Read-only diagnostics classify root cause before mutation and may not mutate project files, persistent data, or running processes.
- High-risk slices may require independent engineering review by a different agent/session.
- Automated mutation paths must be audited fail-closed; unguarded mutation automation blocks closure.
- Closure-critical structured claims may not contradict one another.
- Automated engineering PASS is distinct from human/product/security approval when those authorities are required.
- Never fabricate evidence, identities, outputs, timestamps, hashes, approvals, or commits.

## Status legend

- `[ ] PLANNED` — dependency not PASS.
- `[ ] READY` — dependencies PASS; claim-time checks still apply.
- `[~] IN_PROGRESS` — exclusively claimed.
- `[~] VERIFIED_PENDING_COMMIT` — engineering gate passed; commit policy requires final commit.
- `[~] VERIFIED_AWAITING_OWNER_COMMIT` — engineering gate passed; owner commit is required.
- `[~] ENGINEERING_PASS_READY_FOR_HUMAN_REVIEW` — engineering gate passed; a required human authority is pending.
- `[x] PASS` — closure policy satisfied and all required approvals resolved.
- `[!] STALE_NEEDS_REVERIFY` — previously verified/PASS evidence no longer matches current source/dependency truth.
- `[!] FAIL` — acceptance/gate failed.
- `[!] BLOCKED` — unresolved dependency/environment/coordination issue.
- `[-] PAUSED_GREEN` — green checkpoint; explicit resume/handoff required.
